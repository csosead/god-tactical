## Что построено сейчас (vision-система)

| Файл | Что делает | Статус |
|---|---|---|
| `module/canvas/range-vision.mjs` | База: `Basic Sight` (SIGHT-тип, чистая дистанция) и `Feel Tremor` (MOVE-тип, чистая дистанция, `walls:false` от природы) как обычные Detection Modes. `lightPerception`/`seeAll`/`seeInvisibility` гасятся навсегда. Токен, видимый только через Tremor, рисуется маскировкой — белый квадрат + `mystery-man.svg` под общим magenta-контуром Foundry, толщина рамки и яркость "волны" подкручены сильнее дефолта (см. грабли ниже), сам значок теперь ребёнок `canvas.interface` (не `canvas.primary`), чтобы его не закрашивала тьма/туман. | **Всегда включено**, это основа. |
| `module/canvas/vision-obstruction.mjs` | Опциональный слой поверх Basic Sight: блокировка стенами **через `sight`** (было `move` — развернули вместе с возвратом теней, см. ниже), высокими регионами (кроме Lift-H платформ), и разницей высот (однонаправленно). | **Включено в мире пользователя** (`obstructBasicSight: true`) — по умолчанию в коде всё ещё `false`. |

Плюс поле отступа стен внутрь региона (в игровых единицах) и чекбокс "Учитывать высоту" — копирует `elevation.bottom/top` региона в `flags["wall-height"].top/bottom` сгенерированных стен. Решает: свет/AmbientLight раньше "протекал" сквозь высокие регионы (у региона нет физического тела для рендера света — только у стен), и `sight:None`-эпоха означала, что даже настоящая стена не давала родной тени. | Опционально, per-region галочка. |
| `module/canvas/scene-darkness-opacity.mjs` | Два независимых слайдера в Scene Config → Lighting: **Darkness Opacity** — альфа родного `unexploredColor` шейдера тумана (0=полностью прозрачно/видно карту, 100%=ванильное поведение); **Artificial Darkness Lift** — постпроцесс-фильтр на весь `canvas.stage`, поднимающий ЛЮБОЙ пиксель темнее заданного порога (`max(color, floor)`) независимо от причины темноты (туман, реально заблокированный стеной свет, низкий Darkness Level) — GM-инструмент "ночного зрения", не завязан на fog/vision конкретно. | Оба слайдера, по умолчанию выключены (0%/0%). |
| `module/canvas/range-preview.mjs` | GM-only: два кольца (жёлтое — Basic Sight, фиолетовое — Feel Tremor) вокруг выделенного токена, справочный инструмент. | Без изменений в этой сессии. |
| ~~`module/canvas/region-shadow.mjs`~~ | Была написана в ЭТОЙ ЖЕ сессии как fallback — рисовала полупрозрачный чёрный полигон-"тень" позади высокого региона вручную (выпуклая оболочка + силуэт от наблюдателя). **Удалена** после того, как `region-light-walls.mjs` начал давать РЕАЛЬНУЮ, родную тень от света — самодельный полигон стал избыточен и хуже (не совпадал по силе с настоящими тенями, требовал VisionMaskFilter-костылей). Если это имя всплывёт в старом коде/памяти — файла больше нет, ссылки на него убраны из `god-tactical.mjs`. | Удалено, не восстанавливать без явного запроса. |

**Разворот sight/move (важно, если снова "тень есть, но обнаружение не блокируется" или наоборот):**
Раньше — сознательно: стены `sight: None` везде, `vision-obstruction.mjs` проверял
`move` (не `sight`), ЧТОБЫ родная динамическая тень FOV не появлялась на полу.
Пользователь явно попросил вернуть родные динамические тени → стены обратно на
`sight: Normal` → `_basicSightBlocked` (vision-obstruction.mjs) переключён на
`CONFIG.Canvas.polygonBackends.sight` → `region-light-walls.mjs`'s автостены тоже
ставят `sight: Normal`, не `None`, чтобы не выпадать из этой проверки. **Если это
меняется ещё раз** — искать оба места разом (`vision-obstruction.mjs`'s
`_basicSightBlocked` и `region-light-walls.mjs`'s `_buildAutoWalls`), они обязаны
совпадать.

**Wall Height теперь АКТИВЕН в мире** (был выключен в прошлую сессию, пользователь
включил заново) — и его расчёт высоты глаз (`losHeight = elevation + tokenHeight`)
подтверждён вживую как рабочий с нашими автостенами: подняли токен на elevation,
превышающий `wall-height.top` стены — стена корректно перестала блокировать Basic
Sight (`_testEdgeInclusion` в самом Wall Height, не наш код). Мировые настройки
модуля: `Auto LOS Height` **выключен**, `Default Token Height = 0.4` (не дефолтные
`6`) — то есть высота глаз ВСЕХ токенов без явного `Token Height` на карточке
одинаковая (0.4 + elevation), не зависит от реального размера токена, пока `Auto
LOS Height` не включат или `Token Height` не проставят руками по существам.

## Грабли этой сессии (если что-то из этого повторится — экономит время)

- **`super.staticMethod()` не чинит `this` на класс, где объявлено приватное
  статическое поле.** Подкласс `OutlineOverlayFilter`/`VisibilityFilter` (наши
  `GodTremorOutlineFilter`/`GodVisibilityFilter` в range-vision.mjs/
  scene-darkness-opacity.mjs), переопределяющий `static createFragmentShader()`, при
  вызове `super.createFragmentShader()` внутри своего override — `this` остаётся
  ПОДКЛАССОМ, а не базовым классом. Если родительский метод читает
  `this.#приватноеПоле` (у `OutlineOverlayFilter` это `#quality`) — падает `TypeError:
  Receiver must be class X`, потому что приватные поля не наследуются через
  прототип-цепочку так же, как обычные свойства. **Падало тихо** (Foundry ловит
  исключения хуков и продолжает), маскируя баг несколько сессий — фикс тремор-эффекта
  из прошлой сессии реально ни разу не срабатывал до этой правки. Лечится явным
  ребиндом: `BaseClass.method.call(BaseClass, ...args)` вместо `super.method(...)`.
  Если где-то ещё в проекте есть похожий паттерн (подкласс core PIXI-фильтра с
  переопределением static-метода) — сразу проверять на этот класс ошибок.
- **Мир играет с НЕСКОЛЬКИМИ одновременно подключёнными GM-аккаунтами**
  (`Gamemaster`/`Player2`/`Player3` — все role 4). Любой код с гейтом
  `if (!game.user.isGM) return;` перед мутацией мировых документов (создание/удаление
  Wall и т.п.) гарантированно гонится между всеми тремя одновременно на один и тот же
  broadcast — поймали живьём: `region-light-walls.mjs` создавало 16 стен вместо 4
  (4 клиента параллельно делают clear-then-create, "clear" не видит чужие ещё не
  доехавшие "create"). **Фикс — `game.users.activeGM`** (родной API Foundry,
  детерминированно выбирает ОДНОГО лидера среди подключённых GM) вместо
  `game.user.isGM`. **Не проверено, но подозрительно**: `god-tactical.mjs`'s
  `ready`-хук (`if (game.user.isGM) { ...seedCompendiums, migratePerkToAbility,
  миграция grid сцен... })` использует тот же уязвимый паттерн — не проверяли живьём,
  гонится ли он так же, но структурно та же дыра. Если всплывут странные дубликаты
  документов/повторные миграции — смотреть сюда первым делом.
- **`document.visibilityState === "hidden"` (свёрнутое/фоновое окно браузера) морозит
  ВЕСЬ PIXI-тикер**, включая `canvas.pendingRenderFlags`-дренаж — `Token#visible`
  (закэшированное свойство) перестаёт обновляться совсем, хотя `Token#isVisible`
  (живой геттер) продолжает считать правильно. Половина этой сессии ушла на охоту за
  несуществующим "багом ядра Foundry", пока не обнаружилось, что тестовая вкладка
  Chrome была в фоне (`hasFocus:false, visibilityState:"hidden"`) — Chrome сам глушит
  `requestAnimationFrame` у невидимых вкладок. **При отладке чего-либо
  рендер-зависимого через автоматизацию браузера — ВСЕГДА проверять
  `document.visibilityState`/`document.hasFocus()` первым делом**, и предпочитать
  `object.isVisible` (свежий) вместо `object.visible` (кэш) для диагностики.
- **`TokenDocument.update({x,y}, {teleport:true})` на экстремальные/далеко за
  границами сцены координаты роняет `RegionDocument.segmentizeMovementPath`** (core
  Foundry v13 баг, `#testSamples` падает на `undefined.testPoint`) — не наш код, чинить
  негде. Для программных тест-телепортов — держаться КООРДИНАТ В ПРЕДЕЛАХ
  `canvas.scene.width/height`, не уезжать в условные `±20000`.
- **`CONFIG.Canvas.polygonBackends.sight.testCollision(...)` без `source:
  visionSource` в опциях — Wall Height'овская проверка высоты (`_testEdgeInclusion`)
  молча не срабатывает** (у неё `if (!object) return result;`, `object` берётся из
  `this.config.source.object`). Если тестируете столкновение стены руками через
  консоль — обязательно передавать `source`, `mode`, `priority` так же, как это делает
  `_basicSightBlocked` в vision-obstruction.mjs, иначе результат не совпадёт с тем, что
  реально происходит в игре.

## Как это соотносится со старым планом ("same/below/above")

регионы всё ещё могут блокировать обзор (внутри `vision-obstruction.mjs`) — рост
региона (`elevation.top`) против роста наблюдателя (`eyeHeightForToken`). Никакого
отдельного UI под это на Region Config не появилось — настройка через обычный
`elevation.top`. **Новое в этой сессии:** для регионов с "Автостены" вдобавок
работает НАСТОЯЩИЙ, родной Wall Height 3D-расчёт (`losHeight` наблюдателя против
`wall-height.top/bottom` сгенерированной стены) — токен, поднявшийся выше
`elevation.top` региона, физически перестаёт видеть препятствие, независимо от
`vision-obstruction.mjs`'s собственной 2D-проверки высоты (два независимых, согласных
друг с другом механизма).

  **Wall Height и Levels — БОЛЬШЕ НЕ отключены**, см. таблицу выше — если где-то
  всплывёт старая формулировка "оба выключены", это устарело.
- Макрос **"Lift-H"** (Compendium.world.macros) — без изменений, механика подъёма по
  `region.elevation.top`, `vision-obstruction.mjs` по-прежнему исключает Lift-регионы
  из блокировки обзора по macro UUID.
- **`computeBlindSpot` теперь переиспользуется системой шаблонов оружия** (3D-Direct, см.
  RECENT-CHANGES.md §63): `module/canvas/template-3d.mjs` гоняет его по каждой клетке
  шаблона для точного height-aware отсечения (стены/парапеты), и как основу лучевой
  модели дальнобоя. Новый экспорт **`buildBlindSpotContext()`** (blind-spot.mjs) —
  снапшот стен/регионов один раз, чтобы per-cell вызовы не пересканировали канвас;
  передаётся в `computeBlindSpot` через `options.{fullWalls,walls,regions}`. Если правишь
  `_fullWalls`/`_candidateWalls`/сигнатуру `computeBlindSpot` — держи в уме этого второго
  потребителя, не только оверлей укрытий.
